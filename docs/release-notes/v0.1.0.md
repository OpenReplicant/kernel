# Knowledge Kernel v0.1.0 (draft)

The first tagged release of the Knowledge Kernel.

## What it is

A small knowledge kernel that drops into any agent harness. One Postgres holds every claim, each attributed,
referenced, belief-scored and scoped, and reviewed by a person before it counts. Its three jobs (ingestion,
processing, recall) are done by swappable default modules; everything else is a module too. For developers it is an
agent memory layer over MCP; for organisations it ships as **distributions**, preset bundles that do one job (org and
process maps from conversations, BPM and devops, papers).

## Images

`ghcr.io/openreplicant/kernel:0.1.0` and `ghcr.io/openreplicant/kernel-postgres:0.1.0` (also `v0.1.0`), public. The
distribution bundles (`distributions/*/bundle/`) pull these by default.

## What works

Checked on a fresh clone on 2026-11-27 (Ubuntu 24.04, Python 3.12, rootless Podman 4.9.3, beside other stacks on
the same machine), and by CI on every push:

- `pip install -e .` and `kk up PROJECT`: the stack (Postgres, the kernel, Caddy), the owner's and the agent's own
  logins, the MCP entry, the skill and hooks, and the project read in. An agent over MCP remembered a decision and
  recalled it, cited, with its belief.
- `kk demo`: the order-to-cash process demo, loaded and signed in.
- A distribution bundle from published images (`business`): `podman compose up -d`, then its interview demo.
- The kernel's invariant tests on Postgres 16 and 17 (fresh and upgraded), shape tests, manifests, the module
  catalog, each module's tests, the kernel smoke test with the UI, the module sandbox and devops end-to-end tests.
- The UI shell (a desktop in the browser): search and explain, the review queue, change sets, the graph, view
  modules (BPM, devops, maps), framed apps.

## Known limits

- Kernel v0 (the schema) is frozen; the `kk` command, the module contract's ABI (semver) and the modules may change
  between 0.x releases. No upgrade tooling beyond the schema's own migrations.
- Local first: ports on 127.0.0.1; HTTPS and identity beyond Postgres logins are Caddy's job, not set up for you.
- Tested on Linux only. Docker is the default engine; Podman works with `KK_CONTAINER_ENGINE=podman`.
- Dense recall and re-ranking need the optional `dense` extra (`pip install -e '.[dense]'`); without it recall is
  BM25 and says so.
- The Substrate-specific modules (`encoder-substrate`, `view-substrate`, kernel-mcp's `substrate` profile,
  `constraints-wikidata`) are kept for Substrate's preview and will be retired together later (D-130).
