OpenReplicant · World Model Kernel

What a world model with receipts makes possible

The kernel keeps one model of how a business, a system or a field of research works. Every fact in it is a claim with a source, the words it rests on, a time and a basis. Belief is computed from independent sources, so disagreements stay visible instead of being overwritten. Changes are proposals that a signed-in person approves. Agents read and write the model through MCP, with any model.

This page lists what that enables. It is for anyone curious what the project is, for developers looking for something to build, and for anyone looking for a product to make from it.

The parts every use case draws on

Each use case below names the parts it relies on, in the kernel's own terms.

claims
Every fact cites its source. A reported claim quotes the words it rests on, and the kernel refuses it if they are not there.
belief
Computed from independent origins: ten documents from one author count once. Sources that disagree make a fact contested.
as-of
Two clocks: when a fact was true in the world, and when the model learned it. Ask what was known on any date.
log
Append-only. Replaying it rebuilds the graph exactly, so every past state can be audited.
rules
Policies and targets are normative claims, kept apart from what happens and linked with contradicts when practice breaks them.
seal
What people say is encrypted under a key of their own. Erasing a person destroys the key and leaves the log whole.
decide
A change is a proposal. Only a signed-in person approves it: never its proposer, never an agent.
adapters
Deterministic readers for exports, event logs, repositories and running systems write what they observe.
conform
What was written or declared, checked against what ran. Drift and process conformance are both this.
cite
Answers carry the ids of what they relied on. A sentence that relied on nothing is marked untraced.

Business processes

The process pack maps how work happens as told, as written and as done, with steps joined by flows whose conditions a workflow runtime can run.

  • Process discovery

    Works today

    Map a process three ways: from interviews, from SOPs and from event logs. Deliver the facts the views disagree on, with each side's words and the cases that show it. Where developers can contribute

Each of these extends the kernel without changing it: packs and adapters live in their own folders and reach the kernel only through the gateway.

  • Adapters for structured sources Kubernetes, Terraform state, Prometheus, GitLab and Forgejo forges, Jira and Linear, exports from Odoo, SAP and Xero, HubSpot and Salesforce, HR systems. Start from packs/software/adapter, packs/process/adapter and adapter-kit/.
  • Workflow runtimes Operaton comes first; n8n, Temporal, Camunda 8, Airflow and GitHub Actions could follow. Each compiles the process representation and reads runs back. Start from the process pack's SKILL.md and ADR 0027.
  • New packs Security controls, contracts, care pathways, manufacturing quality, customer research, meetings. Start from docs/packs.md: an ontology in schema.yaml and rules.yaml, a skill, fixtures and tests.
  • Document parsers at the edge MCP servers wrapping existing converters for PDF, Word and slides, so documents reach the gateway as Markdown with no model in between. Start from ADR 0024.
  • Explorer views A BPMN rendering of a mapped process, a timeline with an as-of slider, an inbox of contested facts, swimlane diagrams. Start from ui/site.
  • Evals Annotated sets for process and interview extraction, a cross-paper research eval, a second independent reader. Start from evals/ and evals/annotated/RESULTS.md.
  • Harness integrations and skills Recall hooks for Claude Code and other MCP clients, and skills for new domains in plain Markdown any harness can load. Start from skills/core and skills/interview.

Where it does not fit

  • It is not a metrics store.It keeps observations and summaries. Raw telemetry belongs in a time-series database, read by an adapter.
  • It does not act.The kernel records and answers. Anything that changes a system goes through a proposal a person approved and an adapter outside the kernel.
  • It maps work, not people's performance.Consent before interviews, sealed answers and no personal data in telemetry are part of its design. Using it to score or watch individuals works against that design.
  • It shows disagreement; it does not settle it.People or new evidence settle a contested fact, and the model records how.
  • Extraction is model work.Quotes are checked; interpretation is not. Extraction quality has been measured on SciFact only so far, so review what a model writes before relying on it.

The current phase takes one synthetic company, Northwind, around the whole loop: map it, choose what to automate, automate it, govern what runs.
