# Devops

The MAPE-K loop on a running service: observations, anomalies, a proposed adaptation a person approves, and an actuator that carries it out.

This folder runs the `devops` distribution of the [Knowledge Kernel](https://github.com/OpenReplicant/kernel) from
published images. There is nothing to clone or build.

## Start

```sh
cp .env.example .env              # 1. copy the settings
$EDITOR .env                      # 2. fill in the three secrets (how is written in the file)
podman compose up -d              # 3. start it (docker compose works the same)
```

Images are `ghcr.io/openreplicant/kernel` and `ghcr.io/openreplicant/kernel-postgres`, tag `0.1.0` (set `KK_IMAGE` and `KK_DB_IMAGE` in `.env` for
another release, or `main` to follow the main branch). The packages are public, so pulling needs no registry login. The first start takes a minute while the
database initialises. Check with `podman compose ps`.

## Sign in

Make the owner and install this distribution's modules (the password is printed once as `owner_sign_in`):

```sh
podman compose run --rm init sh -c 'mkdir -p /tmp/p && kk up --distribution devops --no-stack --no-scan /tmp/p'
```

Open http://127.0.0.1:8082/ui/ and sign in as `owner` with that password.

## Load data

devops has no scripted demo (its demo is the devops overlay in the repository, `scripts/e2e_devops.sh`, which needs the source tree). Read your own data with the distribution's modules (docs/modules.md in the repository).

`devops` observes a running service. This bundle has the kernel's side only (the database, the kernel and the UI); the metrics observer and the actuator run as their own sandboxed containers installed with `kk module install` from the repository (docs/demo.md, the devops demo).

## Connect an agent

```sh
podman compose run --rm init kk agent add claude-code      # prints the agent's password once
```

The agent's MCP server is `http://127.0.0.1:8082/mcp` with a bearer token (`podman compose run --rm init kk token agent_claude_code`);
the repository's docs/harness.md covers the harness side.

## Stop, reset

```sh
podman compose down        # stops; the data stays in the volumes
podman compose down -v     # stops and deletes the data
```

Ports are on 127.0.0.1 only. Generated by `kk distribution bundle devops`; do not put anything of yours in this
folder except `.env`, which stays out of version control.
